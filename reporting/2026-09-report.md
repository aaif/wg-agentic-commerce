# [Report] Agentic Commerce – September 2026

**Working Group:** WG Agentic Commerce

**Reporting period:** September 2026

**Chair(s):** Ilya Grigorik (Shopify) & Rahul Bansal (OpenAI)

---

## Summary

The Working Group held three deep dives that together span the layers of an agent-initiated purchase: the Order Network eXchange (onX) for fulfillment and back-office systems, the Machine Payments Protocol (MPP) for headless payment over HTTP, and the Universal Commerce Protocol (UCP) August 2026 release for the agent-to-business layer in between. The three are complementary in scope rather than competing, and the sessions clarified where each hands off to the next. The cross-WG Taxonomy and Landscape workstream also circulated its first batch of agentic-commerce terms for review.

## Progress Against Objectives

**onX (September 2) — the fulfillment layer.** Once a selling channel captures an order, it has to travel through order-management, warehouse, third-party-logistics, and ERP systems to be fulfilled, and inventory, delivery promise, shipment, and return state have to travel back. Today that path is a web of point integrations (EDI, SOAP, file transfer), so channels cannot see real-time inventory or make a credible delivery promise, and agentic channels inherit the problem: checkout protocols capture the order and defer inventory and delivery to a merchant callback behind which the whole chain sits. onX addresses this as an interface contract, not an implementation: fourteen MCP tools (capture, ship, exchange, return, reserve inventory, and similar) and nine shared resources (orders, inventory, products, shipments, and others) over one canonical data model, with each vendor implementing an adapter for its own system. It takes no position on authentication, exposure, or layering with front-office protocols. It is stewarded by the Commerce Operations Foundation, a vendor-neutral 501(c)(6) launched in November 2025 with 60-plus founding members across OMS, WMS, 3PL, ERP vendors and brands; the foundation holds the specification's intellectual property, publishes an open reference server, and runs a board and biweekly technical steering committee. The specification has been public since launch; the presenters described a version 1.0 milestone in August 2026 and a shift to implementer feedback, and characterized the foundation as a multi-year bridge open to an eventual broader standards home. The hand-off to UCP is clean in principle: UCP covers discovery, cart, checkout, and order capture between agent and business; onX carries the captured order into fulfillment and returns operational state. Two patterns can coexist — a front-office protocol exposes standard read and managed order state that plumbs through to onX, or a business exposes onX verbs directly to authorized agents — and delivery promise and live availability need to flow up into discovery, not only checkout. For the **Capability Map** this adds fulfillment-layer actors and rows; for the **Gap Analysis**, no published composition yet exists and authorization across the boundary is unaddressed.

**MPP (September 16) — the payment step.** Agents increasingly pay for things that are not cart-shaped — API calls, inference, content, data access — and the available options are human payment forms (slow, brittle, and penalized by anti-fraud tooling) or bespoke API keys and billing. MPP makes payment an HTTP primitive by reusing the HTTP authentication framework: a server responds 402 with a challenge naming a payment method, an intent (a single charge or a metered session), the amount and currency, and a realm binding that prevents replay against another site; the client picks a method, obtains a credential (for example from a wallet after human approval), resubmits, and receives the resource and a receipt. A server may offer several challenges, a client may declare method preferences, and offers may vary per request. The core is rail-agnostic: cards, bank transfers, buy-now-pay-later, stablecoins, and closed-loop instruments attach as plug-in methods, each specified by its operator, with a core SDK handling control flow. Co-authored earlier in 2026 by Stripe and Tempo, the thin core has been submitted to the IETF, discovery and method specifications sit outside it, methods are listed by pull request, and features enter the core only after traction across methods; the presenters described it as in production use for metered API and inference access. MPP deliberately excludes identity, delegated authority, and risk, expecting identity from existing standards and risk evidence to live inside each method until requirements converge. Its hand-off to UCP is as a payment step: for cart-shaped commerce it points to checkout protocols and could in principle serve as a payment handler inside one, though that composition is untested. For the **Capability Map** this supplies rows — method advertisement, client preference, intent types, origin binding, credential submission — on which x402, wallet flows, and checkout-protocol payment handlers can be compared; for the **Gap Analysis**, no headless payment protocol examined so far carries the mandate or dispute evidence discussed in June and August, and evidence requirements diverge across rails.

**UCP (September 30) — the agent-to-business layer.** UCP defines structured, transport-agnostic business objects for discovery, cart, checkout, and order between an agent and a business, with REST and MCP bindings, so that agents do not drive forms and businesses can state what must be shown to a buyer. The August 2026 release, presented by one of its authors as one input among several, added three things of general interest. Resumable actions let a business pause a workflow for an out-of-band step — first modeled for 3-D Secure — receive the outcome through a callback, and resume, a third pattern between in-protocol field feedback and a one-way URL handoff. Disclosure became structured: typed, extensible policies scoped to line items, and per-response messages whose warnings must be presented, with where buyer consent is attested left open. Identity connected to existing standards: a business advertises supported identity providers so the agent negotiates sign-in through OAuth and OpenID Connect, and an agent-identity layer aligns HTTP message signatures with Web Bot Auth. Vertical-agnostic additions included split payments, payment terms such as deposit and balance, units of measure, retail-location search, and cart permalinks. UCP is governed in public under its own structure — a governing council with per-domain technical councils, notes and governance documents on GitHub — and is expanding from shopping into lodging and food with a horizontal payments group. Members pressed on trajectory: whether the ecosystem converges on a horizontal core plus domain profiles, how domains are chosen, whether optional-attribute conditionality stays tractable for agents as domains add idiosyncrasies, and how merchant-initiated or long-running asynchronous interactions fit a request-response design. For the **Capability Map** this adds resumable prerequisites, disclosure obligations, split tender, and payment terms as rows; for the **Gap Analysis**, consent attestation, verticalization, and asynchronous interaction are recorded as open.
